214: Часть 2. Конкурентный доступ к данным
216: Требование 1. Определение общего ресурса.
217: Необходимо использовать общий ресурс, который уже применялся в ЛР №2 и №3.
219: Требование 2. Конкурентная операция.
220: Запустите:
221: один сервер;
222: два клиента.
224: Оба клиента должны выполнить одну и ту же операцию над одним ресурсом. Запросы должны выполняться одновременно или с минимальным временным интервалом.
226: Требование 3. Использование lock.
227: Необходимо определить критическую секцию и защитить ее с помощью lock:
229: lock (syncObject)
230: {
231: check resource;
233: if (resource available)
234: {
235: reserve resource;
236: return SUCCESS;
237: }
239: return FAIL;
240: }
242: В критическую секцию необходимо поместить все взаимосвязанные действия, которые должны выполняться атомарно относительно других потоков. Не помещать под lock весь метод без необходимости.
244: Требование 4. Проверка результата.
245: Пусть имеется Resource = 1. Два клиента одновременно выполняют:
247: Client 1 → Reserve
248: Client 2 → Reserve
250: Корректный результат:
252: Client 1 → SUCCESS
253: Client 2 → FAIL
255: или:
257: Client 1 → FAIL
258: Client 2 → SUCCESS
260: Но результат:
262: Client 1 → SUCCESS
263: Client 2 → SUCCESS
265: при наличии одного ресурса является некорректным.
267: Требование 5. Логирование.
268: Для демонстрации результата сервер должен выводить журнал выполнения, например:
270: [10:15:01.125] Client 1 → START Reserve
271: [10:15:01.130] Client 1 → LOCK
272: [10:15:01.131] Client 1 → Check resource
273: [10:15:01.135] Client 1 → SUCCESS
274: [10:15:01.140] Client 1 → UNLOCK
276: [10:15:01.141] Client 2 → START Reserve
277: [10:15:01.145] Client 2 → LOCK
278: [10:15:01.146] Client 2 → Check resource
279: [10:15:01.150] Client 2 → FAIL
280: [10:15:01.151] Client 2 → UNLOCK
282: В журнале необходимо отображать:
283: время;
284: идентификатор клиента;
285: операцию;
286: вход в критическую секцию;
287: выход из критической секции;
288: результат операции;
289: при необходимости – состояние ресурса.
