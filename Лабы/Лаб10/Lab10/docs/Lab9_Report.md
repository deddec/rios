## Сравнение Docker / Docker Compose и Kubernetes

| Критерий | Docker / Docker Compose (ЛР №8) | Kubernetes (ЛР №9) |
|---|---|---|
| Основная задача | Собрать образ и запустить контейнеры на одном хосте | Поддерживать заданное состояние развертывания (количество экземпляров, доступ, конфигурация) в кластере |
| Описание конфигурации | `Dockerfile`, `compose.yaml` (императивный запуск сервисов) | YAML-манифесты с `apiVersion`, `kind`, `metadata`, `spec` (декларативное желаемое состояние) |
| Запуск приложения | `docker compose up --build` | `kubectl apply -f ...` создает Deployment, ReplicaSet и Pod |
| Управление экземплярами | `docker compose up --scale` или отдельные контейнеры вручную | `replicas` в Deployment; контроллер сам создает и поддерживает Pod |
| Организация доступа | Публикация порта `5000:5000`, сеть `flower-shop-net` с DNS по именам сервисов | Service с селектором по меткам; при локальной работе — `kubectl port-forward` |
| Изменение количества экземпляров | Пересоздание сервисов (`--scale` только для compose-сервисов) | `kubectl scale deployment ... --replicas=N`, без остановки Service |
| Реакция на удаление контейнера или Pod | `restart: unless-stopped` перезапускает контейнер на том же хосте | Deployment создает новый Pod, если их меньше заданного количества |
| Диагностика ошибок | `docker logs`, `docker compose ps` | `kubectl describe`, `kubectl logs`, `kubectl get events`, статусы Pod |
| Требования к среде | Docker Engine | Кластер (Docker Desktop / Minikube), kubectl, образ, доступный кластеру |

## Ответы на контрольные вопросы

**Что такое Kubernetes и для чего он используется?** Платформа оркестрации контейнеров: описывает желаемое состояние приложения (сколько экземпляров, как к ним обращаться, какая конфигурация) и поддерживает его контроллерами.

**Чем Kubernetes отличается от Docker?** Docker создает образы и запускает контейнеры на одном хосте. Kubernetes управляет развертыванием контейнеров на кластере из нескольких узлов и восстанавливает заданное количество экземпляров. Docker может использоваться внутри Kubernetes как источник образов.

**Что такое Kubernetes Cluster?** Среда, в которой размещаются и управляются приложения: управляющие компоненты и узлы, на которых выполняются Pod. Локально обычно состоит из одного узла.

**Что такое Pod?** Минимальная единица развертывания: один или несколько тесно связанных контейнеров с общими сетью и хранилищем. В ЛР один Pod содержит один контейнер сервера.

**Чем Pod отличается от Docker-контейнера?** Pod — это обертка Kubernetes над одним или несколькими контейнерами. Pod получает собственный IP-адрес, который меняется при пересоздании, и имеет статусы жизненного цикла (Pending, Running, CrashLoopBackOff и др.).

**Что такое Deployment?** Ресурс, описывающий желаемое состояние развертывания (образ, количество реплик, метки, порты, переменные окружения) и управляющий ReplicaSet и Pod.

**Для чего используется параметр replicas?** Задает желаемое количество Pod. Deployment создает замену при удалении одного из них.

**Что такое Service?** Стабильная точка доступа к группе Pod: единый адрес и порт, которые направляют трафик на Pod, выбранные по меткам.

**Почему клиенту неудобно обращаться к Pod напрямую?** Pod пересоздаются и получают новые адреса, их несколько, и клиент не знает, какой из них жив. Service скрывает эти детали и распределяет запросы по доступным Pod.

**Для чего используются метки и селекторы?** Метки — пары «ключ-значение» на объектах; селекторы выбирают объекты по меткам. Deployment находит свои Pod по селектору, Service — направляет трафик на Pod с подходящими метками.

**Что такое YAML и для чего он используется в Kubernetes?** Текстовый формат структурированных данных. В Kubernetes им описываются ресурсы (Deployment, Service, ConfigMap) и их желаемое состояние.

**Как проверить состояние Pod?** `kubectl get pods`, при проблемах — `kubectl describe pod <имя>`, `kubectl logs <имя>`, `kubectl get events`.

**Как получить подробную информацию о Pod?** `kubectl describe pod <имя>`: образ, статус, условия, события.

**Что происходит при удалении Pod, управляемого Deployment?** Pod завершается, Deployment обнаруживает отклонение от `replicas` и создает новый Pod. Удаленный Pod не восстанавливается — создается новый, с другим именем.

**Почему восстановление Pod не гарантирует сохранность данных?** Данные, записанные внутри Pod (в файловой системе контейнера), удаляются вместе с ним. Новый Pod запускается с чистым состоянием. Для сохранности нужны внешние хранилища (БД, тома). В ЛР заказы при отсутствии MSSQL хранятся только в памяти процесса.

**Что такое ConfigMap?** Ресурс для неконфиденциальных параметров конфигурации, которые передаются приложению, например через переменные окружения. Для секретов используется Secret.

**Для чего используются переменные окружения?** Передача параметров процессу во время выполнения без изменения кода и образа. В ЛР — `APP_MODE`.

**Для чего используется `kubectl port-forward`?** Перенаправляет локальный порт компьютера на порт Service или Pod внутри кластера, чтобы клиент на этом компьютере мог обратиться к серверу без публикации Service наружу.

**Почему несколько Pod на одном компьютере не обеспечивают защиту от отказа этого компьютера?** Все Pod работают на одном физическом узле. Если он выйдет из строя, недоступны все экземпляры сразу. Защита от отказа требует нескольких узлов.

**Чем Docker Compose отличается от Kubernetes?** Compose описывает и запускает несколько сервисов на одном хосте; Kubernetes управляет экземплярами на кластере, поддерживает заданное состояние, восстанавливает Pod и предоставляет Service-доступ.

### Ответы на дополнительные вопросы части 3

- **Почему Kubernetes создал замену удаленному Pod?** Deployment хранит желаемое количество Pod (`replicas`). После удаления фактическое количество стало меньше желаемого, и контроллер ReplicaSet создал новый Pod.
- **Как Deployment определяет желаемое количество экземпляров?** По полю `spec.replicas`; текущее значение меняется командой `kubectl scale` или повторным `kubectl apply`.
- **Почему количество Pod может временно отличаться от заданного?** Новые Pod требуют времени на создание, загрузку образа и запуск; Pod может быть в статусе Pending или не пройти запуск из-за ресурсов, образа или конфигурации.
- **Почему наличие трех Pod не гарантирует сохранность данных при отказе БД?** Pod обеспечивают запуск экземпляров, но не хранят данные и не защищают от недоступности внешней БД. Если БД недоступна, все три экземпляра не смогут выполнять операции с данными.
- **Почему масштабирование не всегда приводит к ускорению приложения?** Результат зависит от нагрузки, ресурсов узла (на одном компьютере экземпляры делят CPU и память), узкого места в общей БД и необходимости синхронизации общих данных.
