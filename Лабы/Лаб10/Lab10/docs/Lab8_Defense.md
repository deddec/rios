## Архитектура контейнеризации

- **Один контейнер сервера** — содержит весь функционал ЛР 7 (кластер, консенсус, сервисы, хранилище событий). Отдельные контейнеры для классов внутри одного процесса не требуются (см. требование ЛР 8).
- **Клиент** допускается запускать на хосте или в отдельном контейнере.
- **Сеть** `flower-shop-net` (bridge) обеспечивает взаимодействие по сервисным именам; `localhost` внутри контейнера указывает на сам контейнер.
- **Том** `flower-shop-data` сохраняет файлы журнала и событий при пересоздании контейнера.

## Основные команды

```bash
# Сборка образа
docker build -t flower-shop-server .

# Запуск контейнера
docker run -p 5000:5000 -e FlowerShop__Port=5000 flower-shop-server

# Запуск через Compose
docker compose up --build

# Остановка
docker compose down

# Просмотр логов
docker logs flower-shop-server

# Проверка образов
docker images

# Проверка контейнеров
docker ps -a
```

## Контрольные вопросы (кратко)

1. **Docker** — платформа для создания, распространения и запуска контейнеризированных приложений.
2. **Контейнеризация** — упаковка приложения с компонентами окружения в изолированную среду выполнения.
3. **Контейнер vs виртуальная машина** — контейнер использует ядро хоста ОС (легче), VM имеет полную гостевую ОС.
4. **Docker Image** — неизменяемый образ с файловой системой и инструкциями запуска.
5. **Docker Container** — запущенный экземпляр образа с собственным состоянием.
6. **Dockerfile** — текстовый файл с инструкциями сборки (FROM, WORKDIR, COPY, RUN, EXPOSE, ENTRYPOINT).
7. **ENTRYPOINT** — определяет основную команду запуска контейнера.
8. **Docker Engine** — программная основа для управления образами, контейнерами, сетями.
9. **Docker Desktop** — среда для работы с Docker на настольных ОС.
10. **Docker Network** — механизм сетевого взаимодействия контейнеров по сетевым именам.
11. **localhost внутри контейнера** — указывает на сам контейнер, а не на другой контейнер или хост.
12. **Docker Compose** — инструмент для описания и совместного запуска нескольких сервисов (compose.yaml).
13. **Environment Variables** — параметры конфигурации, передаваемые в контейнер без изменения кода.
14. **Docker Volume** — механизм сохранения данных при пересоздании контейнера.
15. **EXPOSE** — только документирует порт, не публикует его автоматически (нужен -p или publish в Compose).
16. **Контейнеризация и сохранность данных** — данные в изменяемой ФС контейнера теряются при удалении; нужны тома.
17. **Docker vs Kubernetes** — Docker — контейнеризация одного хоста; Kubernetes — оркестрация кластера контейнеров.
