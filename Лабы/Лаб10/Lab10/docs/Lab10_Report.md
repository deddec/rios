## Контрольные вопросы (краткие ответы)

1. **Continuous Integration** — регулярное объединение изменений в общую ветку с автоматической сборкой и тестами.
2. **Continuous Delivery** — проверенная версия автоматически упаковывается в готовый к развертыванию артефакт; выпуск может требовать подтверждения.
3. **Continuous Deployment** — проверенные изменения автоматически разворачиваются без ручного подтверждения. В этой работе реализован именно этот подход.
4. **Pipeline** — последовательность этапов обработки изменений.
5. **Jenkins** — сервер автоматизации сборки, тестов, упаковки и развертывания.
6. **Jenkins Job** — задание, которое Jenkins выполняет по правилам (вручную, по расписанию, по событию).
7. **Pipeline vs Job** — Pipeline описывает последовательность этапов (часто в Jenkinsfile), Job — задание в целом.
8. **Jenkinsfile** — файл с описанием Pipeline, хранится в репозитории вместе с кодом.
9. **Restore** — восстановление NuGet-зависимостей (`dotnet restore`).
10. **Тесты до Docker-образа** — не упаковывать и не доставлять версию, которая не прошла проверку.
11. **При ошибке тестов** — Pipeline получает статус Failed, последующие этапы не выполняются.
12. **Package** — создание Docker-образа с уникальным тегом.
13. **Deploy** — обновление Deployment в Kubernetes новым образом.
14. **Обновление образа** — `kubectl set image deployment/<имя> <контейнер>=<образ>:<тег>`.
15. **rollout status** — ожидание завершения обновления и результат (успех или ошибка).
16. **Доступ Jenkins к Kubernetes** — нужен для выполнения `kubectl` из этапа Deploy.
17. **Poll SCM** — периодическая проверка репозитория на новые commit.
18. **Причины Failed** — ошибка компиляции, падение теста, ошибка Docker, неверное имя Deployment, недоступный кластер, ошибка доступа к Git.
